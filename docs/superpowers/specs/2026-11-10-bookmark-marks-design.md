# 设计文档：侧栏树书签标记（⭐）

日期：2026-11-10
状态：已实现
版本：v0.44.0

## 一、从「已读置灰」到这里

原计划是「已读章节在侧栏树里置灰、未读加绿点」，模仿 GitHub 仓库里「看过的文件」的观感。
核实微信读书网页版目录结构后（见项目记忆 `weread_reader_dom.md`）发现：

- 目录行 `li.readerCatalog_list_item` 的 textContent 里混着 meta 文本「当前读到 40%」「书签」；
- **没有稳定可依赖的「每章已读 / 未读」标记**。

在拿不到真实已读状态时做置灰，只能靠猜（比如「当前章之前的都算已读」），而猜错比不猜更糟
——会把用户没读完的章节标成已读。所以**不做置灰**，改为用目录里真实存在的事实：书签。

## 二、方案

1. `ghCatalogBookmarks(items)`：对每个目录项，取「行文本 − 章节名」后匹配 `/书签/`。
   「减章节名」这一步很关键：章节名本身叫「谈书签」时不能误判成有书签。
2. 渲染时把 `bookmarked` 传给皮肤注册表的 `treeItemHtml()`：
   - GitHub 皮肤：行尾加一个 ⭐（`WRE_SVG.star`，`title="书签"`）；
   - Notion 皮肤：同样 ⭐（对应 Notion 的「pinned」语义）。
3. 星标黄色 `#d29922`，`margin-left: auto` 靠右，12px 大小，不挤占章节名。

## 三、不变量

- 不新增权限 / 联网；不改变目录行的点击与跳章行为（⭐ 只是行内的一个 `span`，点击仍落到行上）。
- 检测只在渲染目录时做一次（随目录缓存），不额外轮询。
- 章节名、meta 拼进 innerHTML 前照旧走 `ghEscapeHtml`（⭐ 是固定 SVG，无用户输入）。

## 四、验收

1. 有书签的章节在 GitHub / Notion 两套皮肤的侧栏树里都带 ⭐。
2. 章节名自身含「书签」二字的、但没有书签的章节不带 ⭐。
3. 无书签的章节行为与之前完全一致。
