# 设计文档：章节查找器（Go to files）+ j/k 翻章

日期：2026-11-10
状态：已确认（用户「下一步」后直接实现）
版本：v0.40.0

## 一、问题

顶栏假搜索框一直写着 `Type / to search`，但：

- 没有任何点击处理，`/` 也没绑定 —— 假 UI 给了一个真承诺却不兑现，比没有更可疑；
- 目录几百章时，只能在左侧文件树里滚动找，伪装得越像、用起来越憋屈。

GitHub 自带的 file finder 恰好是「越像 GitHub、越好用」的控件，所以它必须是**真的**。

## 二、方案

新增模块 `content/disguise/finder.js`（插在 `catalog.js` 之后，复用其目录采集与跳章）：

1. **打开方式**：伪装态按 `/` 或 `t`；或点顶栏假搜索框（Notion 皮肤的 `Search` 同样接上）。
2. **浮层结构**：`#wre-gh-finder` 挂在 `#wre-gh-shell` 内，居中偏上 12vh，560px 宽，
   由输入框 + 结果列表 + 底栏计数组成，配色全部走 `--wre-gh-*` 变量（深浅皮肤自动跟随）。
3. **匹配**：包含匹配优先（按目录原序），再补子序列匹配（「第3章」跳字命中）；
   不做拼音（为它引入字库不值得）。空查询列出全部，最多渲染 50 行。
4. **键盘**：输入框内 `↑`/`↓` 移动、`Enter` 跳章、`Esc` 关闭；点浮层外关闭。
5. **跳章**：统一走 `ghJumpChapter()`（侧栏点击 / 查找器 / `j k` 三条入口共用一份
   「定位节点 → `ghJumpToCatalogEntry`（开面板 → 逐层重试 → 校验章节变化）→ 失败 toast」逻辑，
   只有侧栏点击会额外复制诊断）。
6. **j / k**：伪装态按目录顺序跳到上/下一章。当前章用 `ghCurrentChapterIndex()` 判定 ——
   与侧栏高亮、窗口标题同一判据（先认 `.selected` 标记，再退回高亮类），不再各写一套顺序。
   定位不到就提示，不猜。
   刻意**不做** `gg`/`ge` 首末章：`g` 是伪装开关的救命键，不能为组合键让它延迟响应。
7. **生命周期**：关伪装时一并关闭浮层；皮肤切换重建骨架后，浮层下次打开时按需重建。

## 三、不变量

- 不新增权限 / 联网；章节名拼进 innerHTML 前一律 `ghEscapeHtml`。
- 非伪装态（微信读书原样）下 `/`、`t`、`j`、`k` 完全不被拦截。
- 输入框聚焦时不触发全局快捷键（沿用既有 `handleAllKeyboard` 守卫）。

## 四、验收

1. 伪装态 `/` 或点假搜索框 → 浮层打开、列出全部章节（文件名带 `.md`）。
2. 输入关键字过滤，`↑↓` 切换高亮，`Enter` 跳到该章，浮层自动关闭。
3. `Esc` / 点浮层外关闭。
4. `j` / `k` 上下一章；到首/末章有提示；定位不到当前章有提示。
5. 关伪装后以上全部失效；`?` 快捷键面板列出 G / `/` `T` / `J` `K`。
